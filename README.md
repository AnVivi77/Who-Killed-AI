# Unity 交互艺术解谜展览 · Codex 项目资料包

这是可以直接作为 Codex 项目打开的实施工程。它包含完整需求、素材目录、配置源、验收标准，以及基于现有 Unity 2022.3 工程实现的运行代码和编辑器搭建工具。`UnityProject/` 中的场景/预制体已由 `Tools/Exhibition/Setup Demo` 生成；Unity 编译、Setup/Validate、EditMode 测试和 Mock PlayMode 已在 Unity 2022.3.62f1c1 中实际验证。Vuforia 实体扫描和正式设备验收仍未完成，详见 `docs/08_当前状态与交接.md`。

## 你只需要这样使用

1. 将这个文件夹保存到固定位置。在 Codex 中把 **UnityMysteryExhibition 整个文件夹**作为项目打开，这样根目录的 `AGENTS.md` 和 `docs/` 都在项目范围内。
2. 将你已有的背景、视频、人物、线索素材放到 `SourceAssets/00_Inbox_待整理/`。也可以按照 `SourceAssets/README.md` 分好类。不要因为文件名不规范就重新导出素材。
3. 把 `开始实施.txt` 的内容发给 Codex。它应先检查素材和开发环境，然后持续完成可实施的部分。

已有 Unity 工程：将其完整放入 `UnityProject/`，其中应直接包含 `Assets/`、`Packages/`、`ProjectSettings/`。移动已有工程时优先复制并保留原工程；也可以直接告诉 Codex 已有工程的绝对路径，让它先检查。

没有 Unity 工程：让 Codex 检查本机 Unity 安装后，在 `UnityProject/` 创建。如果本机暂时没有可用编辑器，仍可以先生成脚本、编辑器搭建工具和测试，但不能声称已经在 Unity 中运行通过。

## 已明确的体验

先导视频 → 调查/扫描 → 嫌疑人档案与两条线索 → 两条齐全后播放该嫌疑人事件动画 → 全部完成且最后一段事件动画结束 → 最终总结动画 → 本轮结束。

未发现的线索显示问号。扫描顺序不限。重复扫描不重复计数。展览工作人员可以重置一轮体验。

## 需要你补充的内容

- 真实素材以及“哪条线索属于谁、哪段视频属于谁”的关系。可直接编辑 `content/填写说明.md`，不用懂代码。
- 案件最终文字、实体印刷宽度和正式目标数据库。当前 `content/case.json` 已按用户说明配置为 **5 名主线人物、10 条线索**，但仍保留 `isPlaceholder: true`，未确认的案情文字没有被编造。
- 最终运行设备（手机、平板、其他设备）、横竖屏、Unity 工程位置；未知时先完成编辑器 Mock 演示。
- Vuforia 数据库和许可配置（如已有）。没有时也能先实现其他部分，真实扫描仍需后续配置与实机验证。

素材尚未提供时，所有占位内容必须明确标示“待替换”，不能编造你的案情、人物和最终结局。默认将动画当作已有视频文件；如果你提供 Timeline、Animator 或模型动画，保留同一播放完成接口接入。

## 什么才算做完

实现者需要交付：实际 Unity 工程、已绑定的场景/预制体/配置、无摄像头演示流程、Vuforia 适配、编辑器搭建入口、使用说明和测试结果。编译通过、Mock 通过、真实扫描通过、实机视频通过、展览设备打包通过必须分别记录，不能相互代替。

资料包生成日期：2026-09-04；本次实施更新日期：2026-09-07。当前工程已可在 `UnityProject/` 打开并运行 Mock；尚未附带 Vuforia 许可、真实数据库或正式展览设备配置。

## 素材交付包

在项目根目录运行 `Tools/PackageVuforiaHandoff.ps1`，会按当前 `content/assets.manifest.json` 生成 `Deliverables/` 下的 Vuforia 目标图上传包和完整展览素材交接包。详细步骤见 `docs/12_交付包与后续维护.md`。Vuforia 的 `.unitypackage` 数据库必须在 Target Manager 中根据真实打印宽度生成，不能由本地脚本伪造。
