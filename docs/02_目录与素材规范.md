# 02 · 目录与素材规范

## 两层目录的用途

`SourceAssets/` 保存用户提供的原素材，供整理与追溯；Unity 构建使用的资源需导入 `UnityProject/Assets/ExhibitionCase/`。用户只需提供素材，无需手工建 Unity 资产。

        Environment/CrimeScene/
        Environment/Corpse/

        Clues/DisplayImages/
        UI/
      Audio/Ambient/
      Audio/UI/
      Audio/Voice/
      Video/Intro/
      Video/SuspectEvents/S01/ …
      Video/Finale/
      Vuforia/TargetReferences/

      Data/Generated/
      Prefabs/Systems/
      Prefabs/Vuforia/
      Prefabs/UI/

      Scenes/03_Finale.unity

Vuforia 包和目标数据库必须按所选 SDK 的导入规则放置。资料包的业务目录只是组织建议，不能强行移动 SDK 文件、数据库依赖或其 `.meta` 导致引用失效。

## 素材交接

1. 不知道归类的素材放 `SourceAssets/00_Inbox_待整理/`。
2. 已分类素材放入 `SourceAssets/` 中对应的目录。
3. 实施者将实际相对路径填入 `content/assets.manifest.json` 的 `sourcePath`。
4. 导入 Unity 后生成 `Data/Generated/` 中的素材映射记录，记录源路径、目标路径、GUID 与导入设置；GUID 应从 Unity 获得。

`sourcePath` 相对资料包根目录，统一使用 `/`。缺文件用 `null`，不得用看似存在的虚构文件路径。`suggestedPath` 只是摆放建议，不是已经存在的文件。

## 格式与命名建议

- 原素材文件名可保留中文，剧情显示文本与 ID 分开。
- ID 示例：嫌疑人 `S01`；线索 `CL_S01_A`；目标名 `Clue_S01_A`；视频资产 ID `video_s01`。
- 头像和 UI 图应按用途导入 Sprite；用于目标识别的原图保持与印刷图一致，不能随意裁切、拉伸或加字。
- 线索“识别用图”和“档案中展示用图”可以不同，因此分别有 `targetImageAssetId` 与 `displayImageAssetId`。
- 视频首版优先使用 Unity 导入的 VideoClip 引用。若文件体积或设备要求改为 StreamingAssets 路径播放，统一封装路径与平台差异，不混用未经验证的绝对路径。
- 视频格式、编码和音轨需在最终设备实测；文件扩展名相同不等于一定可播放。
- 中文字体需包含实际文案字形，长文用滚动区，不把所有内容压缩到极小字号。
- 不要求用户提前制作没有的 3D 模型。只有二维背景就以二维背景完成可用原型，场景保留后续模型接入口。

原始大文件不自动删除或压缩。Unity 原工程的 `.meta` 文件应随其资源保留；新资源的 `.meta` 由 Unity 生成。
