# 13 · Unity 项目修改操作手册

适用工程：`UnityProject/`  
当前基准：Unity 2022.3.62f3c1、Vuforia Engine 11.4.4、输出画布 `3840 × 1152`。  
适用内容：素材替换、英文文字、人物和线索增删、档案 Canvas 排版、按钮/状态显示开关、Vuforia 目标更新和验收。

这是一份“改完以后可以继续运行”的操作说明。凡是需要在 Unity Editor 中执行的步骤，都以当前工程已经存在的菜单为准。

## 1. 先记住五个内容来源

| 内容 | 应该修改的位置 | 不要直接修改的位置 |
| --- | --- | --- |
| 人物、线索、英文标题和正文、播放设置 | `content/case.json` | `UnityProject/Assets/ExhibitionCase/Resources/CaseConfig.asset` |
| 素材 ID 与源文件关系 | `content/assets.manifest.json` | `UnityProject/Assets/ExhibitionCase/Imported/` |
| 原始图片、视频、目标图 | `SourceAssets/00_Inbox_待整理/` 或 manifest 中的 `sourcePath` | Unity 生成的 Imported 副本 |
| 档案底图上的图片、卡片和文字坐标 | `UnityProject/Assets/ExhibitionCase/Resources/DossierLayout.asset` | 运行时生成的 `Dossier` 子对象 |
| Vuforia 识别数据 | Vuforia Target Manager 生成的 `CaseTargets.unitypackage` | `StreamingAssets/Vuforia/CaseTargets.dat/.xml` |

项目的稳定主键是 ID，不是中文姓名、数组顺序或文件名。替换素材时通常保留旧 ID；只有确实新增内容时才创建新 ID。

## 2. 每次修改都按这个顺序做

1. 先复制一份项目或至少备份 `content/`、`SourceAssets/` 和 `UnityProject/Assets/ExhibitionCase/Resources/DossierLayout.asset`。
2. 修改源素材和 JSON，不先改 Unity 生成副本。
3. 在项目根目录运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Tools\PackageVuforiaHandoff.ps1
   ```

   这一步会检查 manifest 路径，并重新生成 `Deliverables/` 交接包。

4. 打开 `UnityProject/`，执行 `Tools > Exhibition > Setup Demo`。
5. 执行 `Tools > Exhibition > Validate Case`，先处理 Error，再看 Warning。
6. 需要检查档案排版时执行 `Tools > Exhibition > Build Dossier Canvas Preview`，在 `04_DossierPreview` 场景的 Scene View 检查，不需要进入 Play Mode。
7. 若增删或替换了识别目标，重新生成并导入 Vuforia 数据库，再执行 `Tools > Exhibition > Repair Vuforia Generated Targets`，最后执行 `Tools > Exhibition > Setup Vuforia Webcam` 和 `Tools > Exhibition > Validate Vuforia Setup`。
8. 分别做 Mock、Unity Play Mode 和真实 webcam/目标图测试。只做了 Mock，不能写成“Vuforia 已通过”。

JSON 文件使用 UTF-8 编码；Windows 路径在 JSON 中使用 `/`，例如 `SourceAssets/00_Inbox_待整理/.../new-video.mp4`。

## 3. 替换已有素材

### 3.1 替换视频、人物图、档案底图或显示用线索图

1. 将新文件放进 `SourceAssets/00_Inbox_待整理/` 下合适的文件夹。
2. 在 `content/assets.manifest.json` 找到对应的稳定 `id`，只修改 `sourcePath`；`suggestedPath` 是交接包的推荐命名，不是运行时主键。
3. 保持 `kind` 正确：视频为 `video`，档案/人物/显示线索图片为 `image`，用于 Vuforia 识别的原图为 `targetImage`。
4. 重新运行打包脚本、`Setup Demo` 和 `Validate Case`。

常用 ID 示例：

```text
video_background
video_opening
video_s01 ... video_s05
portrait_s01 ... portrait_s05
dossier_s01 ... dossier_s05
clue_s01_behavior ... clue_s05_information
clue_detective_information
```

视频显示会读取原文件的宽高比。开场结束后 `video_background` 持续循环；事件、Detective 彩蛋和 ending 视频使用 Canvas 上的完整画面区域，按源视频比例适配，不能填满 `3840 × 1152` 的部分显示黑边，不应把视频强行拉伸。不要为了“填满”把源视频改成非等比比例。

如果视频文件被替换但画面仍旧是旧版本，先确认 `sourcePath` 指向新文件，再重新执行 `Setup Demo`；不要只替换 `UnityProject/Assets/ExhibitionCase/Imported/Videos/` 中的副本。

### 3.2 修改英文文字

编辑 `content/case.json`：

- 案件标题：根节点 `title`
- 人物名称：`suspects[].displayName`
- 人物简介：`suspects[].profile`
- 线索标题和正文：`clues[].title`、`clues[].body`

示例：

```json
{
  "id": "CL_S03_INFORMATION",
  "suspectId": "S03",
  "slotIndex": 2,
  "title": "Information",
  "body": "Replace this sentence with the final English clue text.",
  "displayImageAssetId": "clue_s03_information",
  "targetImageAssetId": "clue_s03_information",
  "targetName": "clue_s03_information",
  "physicalWidthMeters": 0.1
}
```

修改后必须重新 `Setup Demo`，因为 `CaseConfig.asset` 是 JSON 生成物。直接在 Inspector 修改 `CaseConfig.asset`，下一次导入可能被覆盖，也会造成内容源不一致。

建议英文文案在进入档案前检查长度：人物简介和线索正文过长会在固定文本框内换行或截断。优先精简句子；如果必须保留长文，再在 `DossierLayout.asset` 增大文字区域或减小字号。

### 3.3 替换 Vuforia 目标图

目标图有两个用途：Vuforia 识别使用原始目标图，档案里的线索照片使用 `displayImageAssetId`。不要把档案显示层的 `uvRect` 裁剪误认为已经修改了 Vuforia 目标图。

如果目标图像素内容发生变化：

1. 更新 manifest 中对应 `targetImage` 的 `sourcePath`。
2. 运行打包脚本，使用 `Deliverables/Vuforia_CaseTargets_*.zip/01_TargetImages/` 中的新图。
3. 在 Vuforia Target Manager 中替换对应 Single Image Target，保持 `targetName` 与 `case.json` 一致。
4. 输入实体打印或手机显示目标的实际宽度。`0.1` 代表 0.10 米，即 10 厘米，不是像素宽度，也不是 `3840`。
5. 检查 Vuforia 特征评级；低评级目标先重新设计图片，不能只靠 Unity 代码修复。
6. 下载新的 Unity `.unitypackage`，导入 Unity 后更新 `StreamingAssets/Vuforia/`。
7. 运行 `Repair Vuforia Generated Targets`，再运行 `Setup Vuforia Webcam`。

不要手工编辑 `.dat` 或 `.xml`。目标图被裁剪、旋转、加水印或重新排版后，也必须重新在 Target Manager 建库。

## 4. 增加一个人物和两条线索

当前规则是每名主线人物恰好两条线索：`slotIndex: 1` 为 Behavior，`slotIndex: 2` 为 Information。人数由配置读取，不需要改代码中的人数。

以新增 `S06` 为例，先在 `case.json` 的 `suspects` 加一项：

```json
{
  "id": "S06",
  "displayName": "New Character",
  "profile": "Final English profile text.",
  "portraitAssetId": "portrait_s06",
  "dossierAssetId": "dossier_s06",
  "eventVideoAssetId": "video_s06"
}
```

再在 `clues` 增加两项，示意如下：

```json
{
  "id": "CL_S06_BEHAVIOR",
  "suspectId": "S06",
  "slotIndex": 1,
  "title": "Behavior",
  "body": "Final English behavior clue.",
  "displayImageAssetId": "clue_s06_behavior",
  "targetImageAssetId": "clue_s06_behavior",
  "targetName": "clue_s06_behavior",
  "physicalWidthMeters": 0.1
},
{
  "id": "CL_S06_INFORMATION",
  "suspectId": "S06",
  "slotIndex": 2,
  "title": "Information",
  "body": "Final English information clue.",
  "displayImageAssetId": "clue_s06_information",
  "targetImageAssetId": "clue_s06_information",
  "targetName": "clue_s06_information",
  "physicalWidthMeters": 0.1
}
```

同时在 `assets.manifest.json` 登记至少这些素材 ID，并让每个 `sourcePath` 指向真实文件：

```text
portrait_s06
dossier_s06
video_s06
clue_s06_behavior
clue_s06_information
```

然后依次运行 `Setup Demo`、`Validate Case`、`Build Dossier Canvas Preview`。新人物没有特殊布局时可以从默认布局开始；若需要精确贴合新档案，见下一节。

最后在 Target Manager 增加两张目标图，下载新数据库，并执行 Vuforia 的修复和设置菜单。只有数据库也包含这两个目标，实体扫描才会生效。

## 5. 删除人物、线索或素材

删除人物时必须一起删除该人物的两条线索；不能只删 `suspects` 而留下孤立 clue。

1. 在 `case.json` 删除该人物对象及其两条 clue。
2. 在 `assets.manifest.json` 删除不再使用的 portrait、dossier、event video 和两张目标图登记；先不要删除 Inbox 原文件，确认新交接包和历史版本后再清理。
3. 运行 `Setup Demo` 和 `Validate Case`。
4. 在 Vuforia Target Manager 删除对应目标并下载新数据库。
5. 导入数据库后执行 `Tools > Exhibition > Repair Vuforia Generated Targets`，再执行 `Setup Vuforia Webcam`。
6. 重新做一遍剩余人物的 Mock 流程，确认 ending 只在最后一个仍存在的人物事件视频结束后播放。

不要通过修改数组顺序来“替代删除”。旧 ID 一旦被其他内容引用，应先全局搜索 `rg "S06|CL_S06|video_s06"`，确认没有遗漏。

## 6. 调整档案 Canvas 排版

档案底图和叠加内容的排版在：

```text
UnityProject/Assets/ExhibitionCase/Resources/DossierLayout.asset
```

它不是 `3840 × 1152` 根画布坐标，而是相对于档案底图本身的归一化坐标。档案 stage 使用底图比例并居中适配，原点在左下角：

```text
Rect(x, y, width, height)
x/y       左下角位置，范围通常为 0 到 1
width     占档案底图宽度的比例
height    占档案底图高度的比例
```

### 6.1 不进游戏预览

执行 `Tools > Exhibition > Build Dossier Canvas Preview`，打开 `04_DossierPreview`。在 Scene View 检查五份档案的：

- 档案底图是否完整显示；
- Behavior 和 Information 图片是否都在各自黑框内；
- 图片是否需要随黑框旋转；
- 右下角水印或多余留白是否需要 `uvRect` 裁掉；
- 标题、正文和问号是否落在对应卡片范围内；
- 长英文是否换行、截断或压到边框。

### 6.2 线索图片和卡片字段

`DossierClueLayout` 每条 clue 主要字段：

| 字段 | 作用 |
| --- | --- |
| `imageRect` | 线索图片显示区域；由 `RectMask2D` 限制在框内 |
| `cardRect` | 红色标题/正文卡片的位置 |
| `rotationDegrees` | 图片框和文字卡片一起旋转，单位为度 |
| `uvRect` | 从源图片取哪一部分，`(0,0,1,1)` 为完整图片 |
| `titleTextRect` | Behavior/Information 英文标题在卡片内的位置 |
| `bodyTextRect` | 已发现线索正文区域 |
| `unknownTextRect` | 未发现时的 `? NOT FOUND` 区域 |
| `titleFontSize`、`bodyFontSize`、`unknownFontSize` | 三种文字字号 |
| `bodyLineSpacing` | 正文行距 |

如果图片超出黑框，优先缩小 `imageRect` 或调整其位置，不要让图片层覆盖底图外部。若黑框本身倾斜，同时修改 `rotationDegrees`；图片和文字卡片会使用相同旋转。

如果只需要裁掉显示图片右下角的 AI 水印，可调整该 clue 的 `uvRect`，例如从右下方向内收；这只影响档案显示，不影响 Vuforia 识别目标。若水印位于目标图本身且影响识别，则必须重新制作目标图、重新上传建库。

### 6.3 人物名称、简介和进度字段

`DossierTextLayout` 控制：

```text
titleRect       人物名称
profileRect     人物简介
progressRect    发现进度，例如 1 / 2
titleFontSize
profileFontSize
progressFontSize
profileLineSpacing
profileAlignment
```

先调 `Rect`，再调字号；不要把字号调到文字越过底图边界。五份现有档案虽然共用一套默认结构，但 S02/S03 等英文较长的人物名或简介通常需要较小字号或更高的文本框。

## 7. 当前运行界面与隐藏入口

当前运行画面已不创建交互按钮、HUD、进度/阶段文字、倒计时、Mock 面板、管理员栏、缺素材占位提示或完成提示。档案底图、人物资料、已发现线索内容和未发现栏的 `? NOT FOUND` 是展览内容，不属于操作提示。

运行时 UI 由以下脚本动态构建：

```text
UnityProject/Assets/ExhibitionCase/Scripts/UI/ExhibitionRuntimeUI.cs
```

屏幕不显示工作人员操作提示，但保留键盘调试入口：F12 重置本轮；仅当 `scannerMode` 为 `Mock` 时，数字键 `1`–`0` 按 `case.clues` 数组顺序触发线索，F9 触发 Detective 彩蛋。正式 Vuforia 模式下这些 Mock 键不会触发扫描。若需彻底移除重置热键，删除 `ExhibitionApp.Update()` 中 F12 的处理，并重新编译验证。

正式扫描配置保持：

```json
"scannerMode": "Vuforia"
```

不要删除 Mock 代码和测试入口，除非已经完成正式设备验收并保留了可回退版本。

## 8. 修改播放时序和交互方式

这些值在 `content/case.json` 的 `settings` 中：

```json
"scannerMode": "Vuforia",
"eventPlaybackMode": "AfterDelay",
"dossierAutoPlayDelaySeconds": 3,
"stableTrackingSeconds": 0.35,
"rearmAfterLostSeconds": 0.5,
"saveProgress": false,
"allowVideoSkip": false,
"autoRestartSeconds": 0
```

- `scannerMode`: 正式扫描用 `Vuforia`；无 SDK 或做无摄像头演示可用 `Mock`。
- `eventPlaybackMode`: 当前无屏幕继续按钮；运行时按定时自动推进，保持 `AfterDelay`。
- `dossierAutoPlayDelaySeconds`: 档案展示秒数，当前为 3。只发现一条线索或重复查看时，超时回调查；新集齐两条时，超时播放事件。
- `stableTrackingSeconds`: 目标稳定追踪多久才接受一次发现；太小容易误触发，太大则难以触发。
- `rearmAfterLostSeconds`: 目标丢失后再次允许稳定识别的等待时间。
- `allowVideoSkip`: 是否允许跳过视频；正式展览建议保持 `false`，确保最后一个事件视频自然结束后才进入 ending。
- `autoRestartSeconds`: 0 表示结束后不自动重开；要自动重开需明确测试一整轮重置行为。

重复扫描不会再次计数，也不会重复入队事件动画。不要通过修改 `CaseProgressService` 的 ID 判断来实现“重复触发”，否则会破坏流程约束。

## 9. 修改输出尺寸和视频比例时的边界

默认输出必须保持 `3840 × 1152`。除非最终设备规格已经改变，否则不要改 `CanvasScaler.referenceResolution`。

- `background.mp4` 是唯一默认全屏填充的动画，当前用户素材正按 `3840 × 1152` 使用。
- 其他视频完整显示并保持源比例；较窄的视频在超宽画布上出现左右黑边是预期行为。
- 不要给所有视频套同一个固定 16:9 比例，否则会造成用户看到的“比例失衡”。运行时会读取实际视频宽高比。
- 如果改了视频编码，优先使用常见 H.264、AAC、MP4，且在目标 Windows 设备上实际验证硬件解码、循环和播放完成回调。

## 10. 修改后如何验收

### Mock 验收

临时将 `scannerMode` 改为 `Mock`，运行 `Setup Demo`，进入 Play Mode：

1. Opening 阶段黑底只播放 opening。
2. Opening 结束后 background 持续循环。
3. 按数字键 `1`–`0` 扫描：映射顺序为当前 `case.clues` 数组顺序；一条线索出现时另一栏为 `? NOT FOUND`，档案 3 秒后自动返回扫描。
4. 扫描同一人物另一条线索：完整档案显示 3 秒后自动播放人物事件。
5. 重复扫同一 clue：不增加计数、不重复入队/播放事件，档案 3 秒后自动返回扫描。
6. 五名人物事件视频全部自然结束后才播放 ending。
7. ending 开始后点 Detective：不播放彩蛋；ending 前点 Detective Information 才播放彩蛋。
8. 用隐藏键 F12 重置，确认下一轮从零开始；按 F9 可单独检查 Detective 彩蛋（仅 Mock 模式）。

### Vuforia 工程验收

运行 `Tools > Exhibition > Validate Vuforia Setup`，确认 Vuforia 类型、License 配置存在、数据库文件和 Image Target 数量正确。需要排查目标状态时，在 `02_Investigation` 的 `VuforiaScannerAdapter` 打开 `logTrackingTransitions`，运行日志应出现类似：

```text
[Exhibition] Vuforia target status: clue_s01_behavior -> TRACKED
```

只有稳定直接追踪达到配置时间才会提交 clue。`DeviceObserver`、`EXTENDED_TRACKED` 或目标丢失不能当作一次新的发现。

### 真实设备验收

必须使用最终 webcam、最终电脑/手机显示或实体打印物、实际目标宽度和正式视频文件逐项验证。当前工程的 Mock、编辑器预览和 Unity Play Mode 通过，不等于真实 Vuforia 识别通过；验收结果应记录到 `docs/08_当前状态与交接.md`。

### 外接 webcam 的选择

当前工程使用 Vuforia 11.4.4 的 Unity Webcam Play Mode。外接 USB 摄像头不是在 `ExhibitionRuntimeUI` 或 `VuforiaScannerAdapter` 中选择，而是在 Vuforia 配置中选择：

1. 先连接摄像头，关闭 Windows Camera、Zoom、Teams、OBS 等可能占用摄像头的程序。
2. 在 Windows 的“设置 > 隐私和安全性 > 相机”中打开相机访问权限，并允许桌面应用访问相机。
3. 在 Unity 打开 `Edit > Project Settings > Vuforia Engine`；如果当前版本界面没有该入口，使用 `Window > Vuforia Configuration`。
4. 将 Play Mode 设为 `WEBCAM`，在 `Camera Device` 下拉框选择外接摄像头的完整设备名，例如 `USB Video Device` 或厂商型号，然后保存项目。
5. 保持 `content/case.json` 的 `settings.scannerMode` 为 `Vuforia`，打开 `Assets/ExhibitionCase/Scenes/00_Boot.unity` 后按 Play。

Vuforia 会把选择的设备名保存到 `VuforiaConfiguration` 的 `WebCam.DeviceNameSetInEditor`。不建议直接编辑 `VuforiaConfiguration.asset` 的 YAML；优先用下拉框选择。Vuforia 官方文档也要求多摄像头时在 `Camera Device` 下拉框选择设备。

本展览故意关闭 Vuforia Video Background，把 `background.mp4` 交给 3840×1152 Canvas 显示，因此 Play Mode 中不一定会看到摄像头画面。这不代表摄像头没有被 Vuforia 读取；可用 Windows Camera 预览画面，同时看 Unity Console 的目标状态日志。若下拉框完全没有摄像头，先在 Windows Camera 中确认设备能工作，再检查设备管理器驱动、隐私权限并重启 Unity。

若外接设备是 HDMI 采集卡、工业相机或只提供厂商专用 DirectShow/API 的设备，它可能不属于 Vuforia 可直接使用的通用 Windows Media Foundation webcam。此时需要厂商提供 Media Foundation 驱动，或另行使用 Vuforia Camera Bridge/Driver Framework；不要把 Unity `WebCamTexture` 预览画面直接当作 Vuforia 输入。

## 11. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 修改 JSON 后 Unity 仍显示旧文案 | 是否重新执行 `Setup Demo`；是否实际编辑了 `content/case.json` |
| 替换视频后仍播放旧视频 | manifest 的 `sourcePath`、文件名大小写、Setup Demo 导入结果 |
| 档案底图不显示 | suspect 的 `dossierAssetId`、manifest 的 `kind: image`、源路径是否存在、是否重新 Setup Demo |
| 图片超出档案黑框 | `DossierLayout.asset` 的 `imageRect`、`RectMask2D`、`uvRect`；不要直接改根 Canvas |
| 黑框倾斜但图片不贴合 | 该 clue 的 `rotationDegrees`，图片框和卡片需使用同一角度 |
| 文字被截断 | 增大 `profileRect/bodyTextRect`，减少字号或精简英文；不要先改变根画布比例 |
| 只有 Detective 能识别 | 检查主线目标特征评级、目标图是否过于平、手机显示尺寸/反光/对焦、目标名和数据库是否完全一致；先不要把问题归咎于 `width` |
| Vuforia 的 Camera Device 下拉框为空 | Windows Camera/设备管理器是否能看到摄像头、相机隐私权限、摄像头是否被其他程序占用、是否需要重启 Unity；特殊采集卡/工业相机还要确认 Media Foundation 支持 |
| 出现 `no stable content mapping` | 检查是否直接追踪到具体 Image Target、目标名和数据库是否匹配；DeviceObserver 本身不是可接受 clue 映射 |
| 删除目标后旧目标仍在场景 | 导入新数据库后执行 `Repair Vuforia Generated Targets`，再 `Setup Vuforia Webcam` |
| Mock 键盘扫描在正式模式触发 | 检查 `case.json` 是否仍为 `"scannerMode": "Mock"`；正式配置设为 `Vuforia` 并重新 Setup Demo |
| 视频变形 | 检查 `ExhibitionRuntimeUI` 的 `AspectRatioFitter` 和播放器报告的真实宽高比，不要用固定比例覆盖所有事件视频 |

## 12. 修改完成检查表

- [ ] 修改的是 `content/` 和 `SourceAssets/` 源文件，而不是 Generated/Imported 副本。
- [ ] 新素材有唯一稳定 ID，且 manifest 的每个 `sourcePath` 都真实存在。
- [ ] 每个主线人物仍恰好有两条线索，slot 为 1/2。
- [ ] 目标图的 `targetName`、Vuforia 数据库名称和工程配置一致。
