# 04 · 流程、UI 与视频

## 四个场景

| 场景 | 内容与退出条件 |
| --- | --- |
| 00_Boot | 加载配置、验证、创建唯一运行时服务，进入开场 |
| 01_Intro | 播放先导视频；自然结束后进入调查 |
| 02_Investigation | 背景/可选模型、Vuforia 或 Mock 扫描、档案 UI、事件视频遮罩 |
| 03_Finale | 最终总结视频；结束后仅保留循环背景 |

系统根对象跨场景保留，场景局部 UI 和相机不持久化。调试直接运行调查场景时允许自举，但必须避免重复系统、EventSystem 和音频监听器。

## 流程状态

```text
Boot → Intro → Investigating
                  ↓ 扫描有效线索
             ShowingDossier (3 秒)
                  ↓ 自动继续
         是否有刚解锁的人物事件？
          否 ↙                 ↘ 是
 Investigating            PlayingSuspectEvent
                                 ↓ 自然结束
                      是否所有线索和事件已完成？
                         否 ↙          ↘ 是
                    Investigating    Finale → Completed

任何管理员重置 → Resetting → 清空本轮状态 → Intro
```

记录“事件视频入队”和“事件视频已结束”是不同事实，不能在扫描第二条线索的同一帧直接认定视频已经结束。

## 关键场景时序

第一条：记录发现 → 打开人物档案 → 已发现栏显示文本/图片，另一栏问号 → 静默展示 3 秒 → 回到扫描。

第二条：记录发现 → 显示完整档案 3 秒（不显示提示或按钮）→ 自动播放此人事件 → 播放结束 → 回扫描或满足条件时进入结尾。

最后一条：完整档案展示 3 秒 → 最后一名人物事件 → 自然结束 → 总结动画。绝不能在最后一次扫描时提前盖住此人的事件动画。

重复线索：重新展示档案 3 秒，进度不变、不重复计数、不自动重播事件，然后回到扫描。

## 档案布局

```text
┌────────────────────────────────────────────┐
│              原档案底图与人物信息            │
├─────────────────────┬──────────────────────┤
│ 已发现：图/标题/正文 │ 未发现：? NOT FOUND  │
└─────────────────────┴──────────────────────┘
```

运行时不叠加按钮、HUD、计数、倒计时或操作提示；线索正文与未发现栏问号属于档案内容。正式界面无需暴露调试 ID、SDK 名或内部错误堆栈。

横向屏幕双栏，竖向屏幕上下排列；适配安全区。文字不得超框，背景保持足够对比度。目标丢失不会关闭屏幕 UI，UI 不挂在随跟踪丢失被禁用的 Target 子物体下。

## 视频服务行为

统一服务处理开场、人物事件、结尾；首版使用 VideoPlayer + RenderTexture + RawImage + AudioSource。播放前等待准备完成；使用结束回调推进状态，不使用预估视频长度的计时器代替结束事件。

- 每次播放有唯一请求标识或取消标识。重置后旧回调不能继续推进新一轮。
- 播放期间只保留一个主视频音轨，环境音暂停或降低；结束后恢复。
- 非循环叙事视频关闭 Loop，处理音轨、宽高比和黑边，避免拉伸。
- 视频预备超时、无法解码、文件缺失需给出重试/管理员操作；正式流程不能默默跳过。
- 缺失视频时不显示占位提示；日志标记缺失媒体并跳过该片段，以便 Mock 流程继续。此行为不能算作真实视频验收通过。
- 回调订阅在停用/销毁时解除；连续进入场景不积累监听器。
- 自动播放延时使用可取消定时任务，且只作为档案阅读时序，不模拟视频结束。

## 重置与恢复

屏幕不显示管理按钮；隐藏键盘快捷键 F12 重置本轮。重置取消媒体和待处理任务，清空发现集合、事件队列、已处理事件、终结标志与档案 UI，然后从开场重新开始。Mock 模式使用数字键 1–0 依次触发配置中的线索，F9 触发 Detective 彩蛋。

默认不跨观众保存。可选保存开启时只写入运行时数据到持久目录，带 schemaVersion/caseId；不使用 PlayerPrefs 保存全部案情。恢复时过滤配置中已不存在的 ID，只恢复稳定检查点；尚未处理的已解锁事件重新排队。保存功能不是首版必要交付。
