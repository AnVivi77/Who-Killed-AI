# 03 · 数据与扫描映射

## 内容数据

内容源是 `content/case.json` 与 `content/assets.manifest.json`。`case.schema.json` 描述配置格式；跨文件引用、两线索约束、ID 唯一性仍须由业务校验器检查。

| Unity 类型 | 主要字段 | 用途 |
| --- | --- | --- |
| CaseConfig | caseId、title、intro、finale、suspects、clues、settings | 整个案件的配置资产 |
| SuspectData | id、displayName、profile、portrait、eventVideo | 人物与事件视频 |
| ClueData | id、suspectId、slotIndex、title、body、image、targetName、targetImage、physicalWidthMeters | 一条线索，slotIndex 为 1 或 2 |
| CaseRuntimeState | discoveredClueIds、resolvedEventSuspectIds、finaleResolved、phase | 当前观众的运行时状态 |

JSON 中资产用稳定 `assetId` 引用；导入后转成 Sprite、VideoClip 等直接引用。每个人的两条线索由 `clues` 中的 `suspectId` 归属查询并按 `slotIndex` 排序，避免又保存一套冲突的线索列表。可以在生成资产中缓存 requiredClues，但它是派生结果。

`isPlaceholder=true` 表示示例内容，不能标为正式内容已完成。实际配置完成后改成 false，并重新导入/校验。玩家进度不写回 ScriptableObject 和源 JSON。

## 进度与事件

`discoveredClueIds` 是发现事实的主来源，使用集合去重。人物“线索齐全”和全案线索齐全由当前配置计算。

`resolvedEventSuspectIds` 记录本轮自动播放已经结束的事件。正式模式仅自然播放结束算完成；用户明确启用跳过时，跳过也可算已处理。调试占位卡的“继续”只能记作 Mock 已处理，不能算真实视频验收。

事件队列、正在播放 ID、正在显示的档案属于流程层。入队时检查：该人物本轮是否已排队、正在播放或已处理，确保一次。重新查看已解锁视频走独立重播路径，不再次标记发现或触发结局。

全案终结门槛：配置有效且人数大于零、每位人物两条齐全、所有必需人物事件都已处理、无档案窗口、无当前视频或待处理事件、结尾未开始。禁止让空列表的“全部为真”直接触发结局。

## Vuforia 映射样例（仅占位）

| Target 名 | clueId | suspectId | 槽位 |
| --- | --- | --- | --- |
| Clue_S01_A | CL_S01_A | S01 | 1 |
| Clue_S01_B | CL_S01_B | S01 | 2 |
| Clue_S02_A | CL_S02_A | S02 | 1 |
| Clue_S02_B | CL_S02_B | S02 | 2 |
| Clue_S03_A | CL_S03_A | S03 | 1 |
| Clue_S03_B | CL_S03_B | S03 | 2 |

每个 ImageTarget 上绑定 `VuforiaClueTarget` 和明确的 `clueId`。目标名用于校验数据库对应关系，不在运行中从名字猜人物归属。

真实接入步骤：检查当前 SDK → 导入用户已有本地数据库，或按官方流程准备目标 → 设置 ARCamera 和许可 → 配置数据库目标及实际尺寸 → 绑定 clueId → 校验每条线索恰有映射 → 逐张实体图实测。账号登录和把用户图片上传 Target Manager 前需取得相应授权；可先使用用户已导出的数据库。

## 扫描触发规则

- 只有 Investigating 接受扫描。档案/视频/结尾期间忽略新发现，不后台累计。
- 默认直接追踪稳定 0.35 秒后触发；此值可配置。使用实际 SDK 的状态类型，不能凭旧例子猜 API。
- 仅靠扩展追踪或有限追踪不创建新的发现；仍已发现的内容不会因状态改变被撤销。
- 每次目标进入视野只触发一次；目标离开直接追踪至少 0.5 秒后重新允许触发。这是防抖参数，可根据现场调节。
- 同一帧多目标满足条件，只处理一个，用稳定规则（先稳定；并列按 clueId）决定，其他等待重新扫描。
- 关闭档案或结束视频后，同一张仍在镜头里的卡不立即重开；提示“移开后再次扫描”。
- 未配置目标显示调试诊断，不崩溃、不错误解锁。

## 数据校验器最低要求

检查案件 ID、正数人数、人物 ID/线索 ID/目标名唯一；每人恰好两个不同槽位；线索归属存在；资产 ID 存在且类型正确；实际 sourcePath 存在；真实目标尺寸为正；开场/结尾/人物视频齐全；所有目标映射齐全；占位内容未进入正式模式。

开发模式可把缺素材列为警告并使用占位 UI。正式构建应把必需素材缺失、占位内容或无效映射作为失败项，不把错误静默转成成功。
