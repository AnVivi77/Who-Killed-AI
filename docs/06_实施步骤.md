# 06 · Codex 实施步骤

这些阶段属于同一个实施任务。每阶段完成相关验证后继续下一阶段；缺失依赖只阻塞实际受影响的工作。

| 阶段 | 实际工作 | 产出与通过条件 |
| --- | --- | --- |
| 0 环境与素材检查 | 检查工程、Unity 版本、渲染管线、包清单、现有报错、素材归属与实际目标设备 | 更新状态文档；明确可执行环境；实际 sourcePath 已登记或保持 null |
| 1 工程与内容层 | 创建/接入工程、目录、JSON 导入器、配置资产、数据校验器 | 能加载样例；更换人数不改代码；无重复 ID、悬空引用 |
| 2 进度与流程 | 发现去重、人物完成、事件队列、扫描门禁、最终门槛 | 测试重复扫描、任意顺序、最后视频先于结尾、无效空配置 |
| 3 Mock 与 UI | 键盘 Mock 扫描、档案双栏和英文内容；不在观众画面生成按钮或额外状态提示 | 无相机也可演示；未知内容不泄露；档案按配置静默计时后继续 |
| 4 媒体 | 开场/事件/结尾播放服务，准备、失败、取消、结束处理 | 每条播放路径可验证；重置不受旧回调影响 |
| 5 场景搭建 | 编辑器生成器、四场景、系统/UI/视频预制体、现有背景和可用素材绑定 | Setup Demo 可执行且可重复；保存重开引用完整；从 Boot 跑通 Mock |
| 6 Vuforia | 核实支持平台、安装实际包、数据库/许可/目标尺寸、追踪适配与绑定 | 有包/无包都能编译；用实体目标逐条记录结果；缺依赖则保留具体未完成项 |
| 7 展览功能 | 重置、终幕、错误处理、屏幕适配、摄像头拒绝/丢失提示 | 连续两轮不串进度；管理员功能不混入正式观众界面 |
| 8 交付验收 | 使用完整内容、目标设备测试、打包与启动说明 | docs/07 有证据；演示和实机验收分别记录 |

## 实施节奏

不要求把所有任务变成一次巨大的改动。先做“一个人两条线索”的可运行路径，再用三人样例和完整配置验证人数扩展。不要先花大量时间装修 UI 而没有验证发现与播放顺序。

每阶段记录：实际改动、验证方法、结果、未解决问题。若有版本控制，可在清晰阶段完成后保留可回退节点；没有现成仓库也不影响本地实施，不自动发布到远程。

## 依赖不足的处理

- 素材缺失：保持 null 和占位标记，给出“哪位人物缺什么”的清单，继续 Mock。
- 无 Unity：编写代码和编辑器搭建入口、检查可做的逻辑；明确尚未在 Unity 编译执行。
- 无 Vuforia：核心与 Mock 继续，真实适配不能通过伪造类型实现。
- 无许可/数据库：完成接入界面、配置校验和手动配置说明；不把用户素材擅自上传外部账户。
- 无发布平台：先做编辑器演示。最终打包前需要用户给出设备，不能根据本机 Windows 就推定其展览平台。
- 有现成工程：遵循已用版本和管线；与 SDK 不兼容时先说明有证据的选项，在不升级工程的前提下完成可行部分。

## 最终需要留下

实际 `UnityProject/`；完整 C# 源码、数据资产、场景、预制体；Mock 演示入口；真实扫描配置与状态；素材导入记录；`docs/08_当前状态与交接.md` 中的运行入口、版本和测试证据；如果已知设备且具备环境，提供该设备可用的构建产物。
